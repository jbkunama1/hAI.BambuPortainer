Zwei fertige Portainer Stacks – das Bambu-Studio-Image baut GitHub Actions automatisch und pusht es auf GHCR, BambuBuddy kommt direkt vom Upstream.

📊

BambuBuddy

🔐

Basic Auth

🔁

Git-Deploy

🌐

LAN-Web-Zugriff

🎛️ Bambu Studio – Web-Slicer

🖥️

Web-UI

Ports 3000 (HTTP) / 3001 (HTTPS) + WebSocket 8082.

🔐

🌙

Dark Mode

Per DARK_MODE=true aktivierbar.

💾

Config-Persistenz

Deploy mit Portainer

Git-Deployment: Der kombinierte Stack liegt als docker-compose.yml in diesem Repo. Bambu Studio pullt das GHCR-Image (pull_policy: always), BambuBuddy das Upstream-Image.

1

In Portainer → Stacks → + Add stack öffnen.

2

Name (z.B. bambustudio) · Build method: Repository.

3

Repository URL: https://github.com/jbkunama1/hAI.BambuPortainer · Reference: refs/heads/main.

4

Compose path: docker-compose.yml.

5

Environment-Variablen setzen (siehe Tabelle unten).

6

Deploy the stack – Portainer pullt das Image, kein Build auf dem Host.

Voraussetzungen

✅ Portainer CE/Business ≥ 2.x

🌐 Internet-Zugriff vom Docker-Host

🔗 Docker-Netzwerk highfishNetwork einmalig anlegen (Networks → Add network).

🔓 Einmalig: GHCR-Paket hai.bambuportainer auf public setzen (Repo → Packages → Change visibility), sonst braucht Portainer Login-Credentials.

Environment Variables

Die wichtigsten Variablen im Überblick – die komplette Liste steht in der README. Eine Vorlage liegt als .env.example im Repo.

VariableBeschreibung
BAMBU_HTTP_PORTExterner HTTP-Port (Bambu Studio). Default: 3000
BAMBU_HTTPS_PORTExterner HTTPS-Port (Bambu Studio). Default: 3001
BAMBU_WS_PORTExterner WebSocket-Port (Bambu Studio). Default: 8082
CUSTOM_USER / CUSTOM_PASSWORDBasic-Auth-Zugang für Bambu Studio. Default abc/abc – unbedingt ändern!
DARK_MODEDark Mode für Bambu Studio (true/false). Default: false
BAMBU_BUDDY_PORTExterner Port für BambuBuddy (Container-Port ist 8109). Default: 8060
PUID / PGIDBenutzer-/Gruppen-ID für Dateiberechtigungen. Default: 1000
TZZeitzone, z.B. Europe/Berlin
